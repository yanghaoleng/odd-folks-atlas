# 为自己的部署启用登录编辑

默认 `npm start` 仍然只读，不附带默认账号或密码。以下步骤由部署者在自己的服务器上手动执行；本项目不提供官方托管或对外 SDK/API 支持。

内置方案是单管理员六位 PIN，适合小规模自用，不适合将多人或高价值数据的保护仅托付给一个六位密码。公网部署应额外配置反向代理登录限速及访问控制，例如 IP 允许名单、VPN 或代理认证。不要记录登录请求正文。运行进程使用普通专用用户，不需要 root。

## 1. 选择并设置自己的 PIN

在项目目录运行：

```sh
node service/provision-auth.cjs "$HOME/.odd-folks-atlas-auth"
```

在终端隐藏输入自己选择的六位数字，然后回车。不要使用文档、测试或演示中的数字作为真实密码。程序只接受标准输入，不接受命令行参数或环境变量中的明文密码，不回显或记录密码。Ctrl+C 取消。

工具新建私有目录（0700）和凭据文件（0600），仅保存随机盐和 scrypt 摘要。若目录已存在且权限过宽会拒绝操作，不会修改其权限；若凭据已存在也会拒绝覆盖。请自己选择尚未存在的专用目录，不要使用共享目录、dist、网站静态根目录或代码仓库作为认证目录。不要提交、公开、备份到公开存储或发送 credentials.json、sessions.json。

## 2. 配置 HTTPS 站点并启动

先由自己配置 HTTPS 反向代理，将站点流量转发至本机 127.0.0.1:4180。替换下面的示例域名为自己的实际来源地址，不要附路径或末尾斜杠：

```sh
ATLAS_ORIGIN=https://atlas.example \
ATLAS_AUTH_DIR="$HOME/.odd-folks-atlas-auth" \
ATLAS_DATA_DIR="$HOME/.odd-folks-atlas-data" \
npm start
```

`atlas.example` 是占位示例，不是可用的托管服务。启动器要求明确的 HTTPS 来源和绝对私有认证目录；缺失、损坏或权限不安全时启动失败，不会悄悄开启匿名写入。不要将后端端口直接暴露公网。

随后打开自己的 HTTPS 站点，点击“登录编辑”，输入 PIN。未登录仍可浏览、预览和下载，但无法保存或上传。登录成功后可以保存配置、修改资源定义及上传 PNG；可点击“退出登录”撤销当前会话。

会话 Cookie 使用 Secure、HttpOnly、SameSite=Strict 和 `__Host-` 前缀，仅适用于 HTTPS。同源写入还校验精确 Origin；没有 Origin 的写请求不能冒充浏览器会话。不要为了 HTTP 部署移除这些保护。

## 限速、持久化和维护

- 默认会话有效期 30 天，服务器只存会话令牌摘要。
- 默认累计 8 次失败尝试后锁定 15 分钟，状态持久化，重启不能清除锁定。这是全局防护，攻击者可能造成暂时拒绝登录，因此仍需要代理层限速与访问控制。
- 单个认证目录只允许运行一个写入进程；正常退出会释放锁。
- 更换密码：先停止服务，为一个新的私有认证目录重新运行初始化工具，再更改 ATLAS_AUTH_DIR 并重启。旧目录中的会话不再生效。旧目录应按部署者自己的私有备份和清理策略处理。
- 不要启用 `--local-demo` 后通过代理或隧道开放公网。该模式仅用于 127.0.0.1 本地开发，与会话模式互斥。

认证单元测试和集成测试只使用临时目录中的固定假凭据，覆盖登录、持久化限速、注销、过期、伪造 Cookie、跨来源拒绝、初始化权限及覆盖拒绝。运行 `npm test`。
